# Changelog

All notable changes to `@ichava/js-icon-components` follow [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **The release checks its tarball against the install URL.** `scripts/check-release-name.mjs` runs in `release.yml` after packing and before publishing, and fails unless the release directory holds the full tarball under the exact name `tarballUrl()` in `scripts/prepare.mjs` gives for the tag (the command an `"install": "tarball"` refusal prints) and `SHA256SUMS` lists it. Pre-release tags are checked the same way. `tests/release-name.test.ts` covers final and pre-release tags, a drifted name and the workflow step's place (proven red by renaming the file in `tarballUrl()`, and by removing the step).

### Changed

- **The install docs offer both paths in order.** The README's Install and `docs/installation.md` lead with the release tarball (`npm install` of the release URL, and the `SHA256SUMS` check), for an install with no build, then the git install, for contributors or a pinned commit. The git install itself is unchanged.

## [0.1.0] - 2026-11-13

First release.

### Added

- **`"ichava": { "icons": { "install": "tarball" | "build" } }`**, also `ICHAVA_ICONS_INSTALL`, makes the install path a setting. `tarball` stops a git install and prints the release tarball command for this version; `build`, or no key, is today's git build; any other value fails the install, listing the two. A built `dist/` is never refused, so the tarball itself installs as before. `tests/prepare.test.ts` covers each value (proven red by disabling the refusal).
- **Three Tier 3 flavours** (icon-browser schema 1.6.0, now 1.8.0, vendored with its digest): Qwik (`./qwik`, one lightweight component per icon; Qwik's server renderer and optimizer in the test), Ember (`./ember`, a template-only Glimmer component in template-tag format, compiled with content-tag and checked by the Glimmer precompiler) and Elm (`dist/elm/Ichava/Icons/<Pack>.elm`, one `Svg msg` function per icon, compiled with `elm make` from npm's `elm` package and run in jsdom in the test). `@builder.io/qwik` and `ember-source` are optional peers.
- **Four asset exports** under `dist/assets/<pack>/`, chosen in the same `ICHAVA_ICONS_FLAVOURS` list as the flavours: `icons.css` (CSS mask, one `.i-<pack>-<slug>` class per icon), `data-uri.json` (percent-encoded SVG data URIs), `flutter.zip` (SVG assets, Dart path constants and a `pubspec` fragment for `flutter_svg`) and `swiftui.zip` (an `.xcassets` catalog, `template` rendering for one-colour icons, `original` otherwise). All four carry SVG: the ichava icon ecosystem is strictly SVG. Every export is written from the parsed, policy-checked tree, carries the pack's attribution, and is counted from its files by the count guard.
- **Illustration props.** `primaryColor` (sets `--ichava-primary` and `color`) and `variant: 'light' | 'dark'` in every component flavour (`primary-color` and `variant` attributes on the Web Component). `packs.json` takes `themeVariants: { "dark": "-dark" }`, core's twin rule: `scene-dark.svg` becomes `variants.dark` of `scene.svg`. Exercised in React, Vue, Svelte and the Web Component with a test-only pack of three CC0 shapes, `tests/fixtures/packs/illustration-demo`.
- `scripts/pack-tarball.mjs`, which `release.yml` and the tests both pack with.
- Guards: the registry guard reads all 25 formats of schema 1.8.0 and requires every `generated` and `asset` one (twelve flavours, four exports: 16 generator-owned formats) and none of the `laravel` or `client` ones; golden output and a structural check for each export (CSS parses, `pubspec` parses as YAML, `Contents.json` against Apple's documented keys); every file an export writes, and every zip entry, is SVG, CSS, JSON, Dart or YAML or the pack's attribution; Elm lines stay under the parser's 16-bit column limit; two per-pack tarballs install side by side.

- A generator that reads each pack in `packs.json` from git at a pinned commit (the sibling checkout when it holds the commit, else a shallow fetch) and writes one data module plus React, Vue 3, Svelte 5 and Web Component modules per pack. The first pack is `ichava/icon-sets-tabler` at `10a5f39c`: 6,257 icons per flavour.
- Four templates, one per flavour, each compiled by that framework's own compiler in its test and render-snapshotted for three icons. Every icon takes `size`, `color`, `title` and, on stroked icons, `strokeWidth`; it is `role="img"`, and `aria-hidden` unless titled.
- An SVG gate that applies `ichava/core`'s policy (allow-list, `#fragment` references only, 30,000 elements, 4,500,000 bytes) and rejects rather than strips, so one bad icon fails the build.
- Guard tests: hostile SVGs are rejected; the output count per flavour equals the input count, above a floor; every flavour is a `generated` format in icon-browser's format registry and the reverse; no lock file is tracked.

### Changed

- **The install docs name the real `v0.1.0` release.** `docs/installation.md` opens with a choice between the tarball and the git build, gives the full and per-pack tarball URLs, shows how to check one against `SHA256SUMS`, and pins git installs to `#v0.1.0`; the README's Install section follows. Both said there was no release yet.
- **Every pin names its source's v0.1.0 root** for the re-squash, which gives each repository one root commit with the tree of its `main`: the packs at tabler `eddbd69f`, flag `5acfe40c`, twemoji `b0d686fb` and openmoji `4c06bb6e` (each on GitHub now as branch `release/v0.1.0-root`, so the build's shallow fetch works before and after the squash), and `vendor/source.json` at core `9bd8b3a9`, icon-browser `97631b19` and react-icon-browser `054c2b32`. The trees hold the same SVGs as the previous pins; the copies' digests are unchanged.
- **The vendored SVG policy and icon-browser schema name their sources' v0.1.0 roots**: core `c2d79a6b` and icon-browser `466b8fb1`, the root commits the re-squash cuts from today's `main` of each. Both files are byte-identical at those trees (SHA-256 unchanged).
- **The Twemoji pack is `twemoji`, from `ichava/icon-sets-twemoji` at `48f232c7`** (ichava/icon-sets-twemoji#103), up from `eed0ae90`. The pack was renamed from `ichava/icon-sets-emoji`, forward only, so its entry in `packs.json` takes the new repository and checkout, and its id moves from `emoji` to `twemoji` with no alias: the import subpaths are `@ichava/js-icon-components/<flavour>/twemoji`, the assets `dist/assets/twemoji/`, the per-pack package `@ichava/js-icon-components-twemoji`, and `ICHAVA_ICONS_PACKS` takes `twemoji`. The SVGs are unchanged (3,435). README, docs and tests follow.
- **The SVG policy interpreter follows react-icon-browser at `876bba9`**: the policy is narrowed by `isSvgPolicy` at load instead of cast (re-audit F-15). Body re-copied byte for byte; `vendor/source.json` records the new commit and digest.
- **The install docs promise nothing that does not exist.** There is no tag or release yet, so the README and `docs/installation.md` install from git (the default branch, or a pinned commit) and describe the release tarball without naming a tag. `tests/install-docs.test.ts` fails when the README or a docs page names a tag (`#vX.Y.Z`, `/releases/download/vX.Y.Z/`) that `git tag -l` does not list; CI checks out with tags. `docs/release.md` is exempt, since it names the tag it tells you to cut.
- **The SVG policy interpreter is pinned to its source.** `src/generator/svgPolicy.ts` is the runtime preamble, a marker, then react-icon-browser's `svgPolicy.ts` from its second line, byte for byte (`c9707562`, which adds the `PRESENTATION_ATTRIBUTES` export the hand copy had lost). `vendor/source.json` records it under `interpreters`, and `tests/vendored.test.ts` pins the body by digest and compares it with the sibling checkout when present.

- **Every pack is pinned at its current `main`** (Q35): tabler `98b4b8ca` (from `10a5f39c`), flag `6e995e95` (from `2d7b51ce`), emoji `eed0ae90` (from `833f11fb`) and openmoji `8e51250f` (from `44d4dba5`). Emoji is Twemoji only since icon-sets-emoji#99, so its one licence file (`licenses/twemoji/license`) needs no explicit `attribution` list; flag now ships its upstream `licenses/flag-icons/LICENSE`, which the convention copies beside `ATTRIBUTION.md`. The four packs generate 18,802 icons (6,257, 542, 3,435 and 8,568); the docs said 17,365.
- **Each vendored file records its source.** `vendor/source.json` names the repository, path, commit and SHA-256 of `svg-policy.json` (core `49938407`) and `icon-browser.schema.json` (icon-browser `3531662d`, whose `$id` now resolves). `tests/vendored.test.ts` pins every digest, requires every vendor file to be recorded, and compares a copy with its canonical file when that repository is checked out beside this one (or under `ICHAVA_PACKAGES_DIR`); without the checkout it is skipped, not silently passed.
- **No private pack is named** in `packs.json`, `docs/packs.md` or the generator's comments.

- **The openmoji pack is pinned at `44d4dba5`** (ichava/icon-sets-openmoji#9), up from `25280ae1`, and generates all 8,568 SVGs. The re-sync on icon-sets-sync#92 dropped the unused `xmlns:sodipodi` from the Cornwall flag in both sets, so its two `exclude` entries are gone; the build fails on an entry that passes. The openmoji entry has no `exclude` list now.
- **Attribution files are found by convention.** `resolveAttribution` reads, at each pack's pinned commit, its `ATTRIBUTION.md` and every file under `resources/assets/svg/licenses/`, so `packs.json` no longer names them and a pack renaming its licence (icon-sets-openmoji#8, `LICENSE` to `LICENSE.txt`) needs no edit here. `attribution` stays as an optional override; an entry that names no file at `ref` fails the build, as do a CC-BY or CC-BY-SA pack with none and two files that would share a basename. The four packs ship the same files as before. `tests/attribution-convention.test.ts` renames a licence between two commits of a throwaway pack and checks both ship it; against the old code it failed.
- **The openmoji pack is pinned at `25280ae1`** (ichava/icon-sets-openmoji#7 and #8), up from `d492519e`: 8,568 SVGs, generated as 8,566. Its `attribution` names `resources/assets/svg/licenses/openmoji/LICENSE.txt`, the upstream licence that replaced the hand-placed `LICENSE` in #8, so `dist/<flavour>/openmoji/` now carries `LICENSE.txt`. The high-speed-train `exclude` is gone (fixed upstream in #4, and the build fails on an entry that passes). Two new entries exclude the `uncategorised/1f3f4-e0063-e0061-e0071-e0063-e007f.svg` flag in both sets, which keeps an unused `xmlns:sodipodi` declaration the gate rejects.
- **The flag pack is pinned at `2d7b51ce`** (ichava/icon-sets-flag#94), up from `67075d3f`, so the generated US and UM flags carry their stars: the four `us`/`um` icons now hold the `<marker>` and its `marker-mid` reference, which the sanitiser accepts since ichava/js-icon-components#9. Still 542 icons. `docs/packs.md` names the commit.
- **Each per-pack release tarball is its own package**, `@ichava/js-icon-components-<pack>`, with the same subpath exports; the full tarball keeps `@ichava/js-icon-components`. They used to share the full package's name, so npm kept only one: installing a second replaced the first. Imports from a per-pack tarball now name it (`@ichava/js-icon-components-tabler/react/tabler`). The tarball checker refuses a per-pack tarball with the shared name.
- The full release tarball is 49.6 MB to download and 249.4 MB unpacked (was 7.0 MB and 64.2 MB), almost all of it the asset exports, and installs offline in about 12 s. Per-pack tarballs are 7.6 to 23.5 MB (measured 2026-11-04, after the PNG and Android VectorDrawable exports were dropped; with both the full tarball was 133.4 MB and 358 MB, and with the Android export alone 62.3 MB and 266.1 MB). A git build that lists only its flavours writes no export.
- `manifest.json` gains `assets`, `unbuilt.assets` and, per pack, `assets` and `variants`.

- **Prebuilt release tarballs, the default install.** `release.yml` builds once and attaches `ichava-js-icon-components-<version>.tgz` (`npm pack` output, every pack and flavour), one `ichava-js-icon-components-<pack>-<version>.tgz` per pack, and `SHA256SUMS`, each checked by `scripts/check-tarball.mjs`. `npm install <release URL>` needs no compiler, `git` or configuration. The workflow runs on a `v*` tag push or on dispatch with a `tag` input, and creates or updates that tag's release only.
- **A configurable git build.** `prepare` is now `scripts/prepare.mjs`: it builds only when `dist/` is missing, builds nothing on `ICHAVA_ICONS_SKIP_BUILD=1`, and otherwise builds the packs in `ICHAVA_ICONS_PACKS` for the flavours in `ICHAVA_ICONS_FLAVOURS`, falling back to `"ichava": { "icons": { … } }` in the installing application's `package.json`. Measured: a git install of `tabler` for `react` is 12 MB in 23 s, against 126 MB in 61 s for everything.
- A pack or flavour left out of a build keeps its subpath as a stand-in that exports the real names and throws naming the variable that adds it; `manifest.json` lists them under `unbuilt`.
- Guards: the packed tarball holds `dist/` for every pack and flavour and no source, tests or dependencies; it installs offline into a scratch application and imports an icon in every flavour with no compiler present; a selective build writes only what it selected, and its stand-ins throw.

- The registry guard requires all nine flavours. The five Tier 2 ids are in icon-browser's format registry since schema 1.5.0, so `tests/registry.test.ts` now asserts each is a generated, copyable format there and that no other generated format exists, and the vendored `vendor/icon-browser.schema.json` is refreshed to 1.5.0 (digest updated). The "stays pending" assertion is gone.
- Three packs: `flag` (`ichava/icon-sets-flag` at `67075d3f`, 542 flags in `4x3` and `1x1`), `emoji` (`ichava/icon-sets-emoji` at `833f11fb`, the 3,435 Twemoji icons) and `openmoji` (`ichava/icon-sets-openmoji` at `d492519e`, 7,131 icons in `openmoji-color` and `openmoji-black`). `icon-sets-bundled` is not generated: it is private and for internal and client use only.
- Per-icon id prefixing: every `id`, and every `url(#…)`, `href`, `xlink:href` and ARIA id reference to it, becomes `<pack>_<set>_<name>_<id>`, so two icons on one page never share an id.
- Artwork licences travel with the icons: each pack's `ATTRIBUTION.md`, and its licence text where it has one, is copied from the pinned commit to `dist/<flavour>/<pack>/`; each generated module carries a `/*!` legal comment; `manifest.json` lists each pack's `licence`, `excluded` and `attribution`.
- `packs.json` fields `licence`, `attribution`, `categories` (one level of category directories) and `exclude` (rejected SVGs left out, each with a reason; a stale entry fails the build).
- Guards: output equals input per pack, less listed exclusions; no repeated id on a page of icons from one pack or two; every multi-colour flag and emoji keeps every source colour; attribution files present for every pack and flavour.

- Five flavours, each an optional peer with its own subpath, template, compile test and render snapshot: React Native on `react-native-svg` (`./react-native`), Angular as a standalone `ichava-ng-icon` component compiled by `ngc` in partial mode (`./angular`), SolidJS (`./solid`), Preact (`./preact`) and Astro (`./astro`, shipped as `.astro` source). Their format ids (`reactNative`, `angular`, `solid`, `preact`, `astro`) are listed in icon-browser's registry from schema 1.5.0 and required by the registry guard.

### Removed

- **The Android VectorDrawable export (`android-vd`, `dist/assets/<pack>/android-vd.zip` and `android-vd-skipped.json`), by owner rule (2026-11-04): the ichava icon ecosystem is strictly SVG.** It never shipped in a release. icon-browser's schema 1.8.0 (ichava/icon-browser#131) drops the id, re-vendored here with its digest; `ASSET_TARGETS`, `NATIVE_TARGETS`, `ASSET_FILES`, `androidZip`, `androidName`, `src/native/vectordrawable.ts` (`toVectorDrawable`), its count check, the manifest's per-pack `skipped`, `scripts/check-tarball.mjs`, `docs/tools/android-vd.md` and `tests/vectordrawable.test.ts` go with it. `ICHAVA_ICONS_FLAVOURS=android-vd` now fails as an unknown name. `tests/registry.test.ts` requires 16 generator-owned formats and asserts `android-vd` is absent, and `tests/assets.test.ts` fails if an export writes any file that is not SVG, CSS, JSON, Dart or YAML (or the pack's attribution).
- **The PNG export (`png-zip`, `dist/assets/<pack>/png.zip`), by owner decision (2026-11-04).** It never shipped in a release. icon-browser's schema 1.7.0 (ichava/icon-browser#129) drops the id, re-vendored here with its digest; `ASSET_TARGETS`, `ASSET_FILES`, `pngZip`, `PNG_SIZES`, the count check, `scripts/check-tarball.mjs`, `docs/tools/png-zip.md` and the `@resvg/resvg-js` development dependency go with it. `ICHAVA_ICONS_FLAVOURS=png-zip` now fails as an unknown name. The full build takes about 15 s instead of 27 s.

### Fixed

- **`<marker>` is accepted, so the US and UM flags can keep their stars.** Both draw the fifty stars as one `<marker>` repeated by `marker-mid="url(#us-a)"`, and the vendored policy did not allow `<marker>`. `vendor/svg-policy.json` is re-synced to sha256 `49ee43ce` (ichava/icon-sets-sync#91, ichava/core#166): `<marker>` with `refX`, `refY`, `markerWidth`, `markerHeight`, `orient` and `markerUnits`. A marker carrying a script, an `on*` handler or an external `href` is still refused, and so is `marker-*` aimed at an external url. The React Native flavour maps `marker` to react-native-svg's `Marker`, which its element guard asked for. `tests/fixtures/svg/presentation-vectors.json` gains 8 attribute rows and 6 document rows, which `presentation.test.ts` runs. The pinned flag pack still ships the star-less files until `packs.json` moves to a re-synced commit.
- **The generator accepts `display`, `color` and `marker-*`, each behind a value guard** (parity with ichava/icon-sets-sync#85 and ichava/core#163). `vendor/svg-policy.json` is core's new policy (sha256 `7a7c07fd…`, pinned in `tests/vendored.test.ts`). `presentationValueIsSafe` in `src/generator/svgPolicy.ts` is the same as react-icon-browser's: `display` must be bare keywords, `color` must pass `cssValueIsSafe`, and `marker-*` must be `none` or `url(#id)`. Anything else is still rejected. Stray text is still rejected rather than stripped, so the openmoji `high-speed-train` exclusion stays. Regenerated output is byte-identical: no icon changed in the four shipped packs (17,532 dist files). Across all 142,247 pack SVGs, 14 decisions changed, all in icon-sets-bundled, which is not generated. `tests/presentation.test.ts`, with `tests/fixtures/svg/presentation-vectors.json` shared with core and react-icon-browser.
- The React flavour passes a source `style` attribute as an object. React throws on a string, so the eight flag SVGs with `style="marker:none"` and similar could not render.

### Security

- **The release workflow reads by default and writes only in its one job**, and its `actions/setup-node` step restores no package-manager cache (zizmor `cache-poisoning`). An npm `overrides` entry lifts the dev-only `minimatch` past GHSA-g3hv-75wg-m249; `npm audit` on a fresh install: 10 moderate before, 0 after.
